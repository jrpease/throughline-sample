# Card

_Groups related content and actions about a single subject._

A container that gathers everything about one subject — a person, a product, a project — so it reads as a single unit in a list or a grid. Give each card one clear main action; a card with several competing actions stops being one unit.

## When to use

- Several pieces of information belong to one subject and should be scanned together.
- The page shows a list or grid of comparable items.

## When not to use

- You need page-level layout structure. Use the page's own layout instead.
- The content is a plain run of text with nothing to group. Leave it ungrouped.

## Do

- Make the main action obvious.
- Keep one main call-to-action per card.

## Don't

- Don't nest cards more than one level deep.
- Don't make the card and a button inside it separately clickable.

## Variants

### variant

- `default` — The everyday choice, separated from the page by a thin edge.
- `elevated` — Lifts off the page, for a card that sits above other content or needs emphasis.

## Accessibility

- A card is just a container with no meaning of its own. Add a role and a name only when it is a landmark region or is itself clickable.
- If the whole card is clickable, give it an accessible name and make it reachable by keyboard.
- Don't let the lift be the only thing carrying meaning; anyone who can't see it needs the same information in words.
