# Input

_Collects a single line of free-form text._

A single-line field for text the user types themselves, like a name, an email address, or a search query. It always needs a visible label, and the error state is what most changes how you use it: reserve room for the message so the layout doesn't jump.

## When to use

- The answer is short, open-ended text that you can't offer as a list of choices.
- The user is searching or filtering and needs to type freely.

## When not to use

- The answer comes from a fixed set of options. Use Select for many choices or Radio for a few.
- The answer runs to several lines, like a comment or a description. Use Textarea.

## Do

- Pair every field with a visible label.
- Put format hints in helper text.
- Reserve space for the error message.

## Don't

- Don't use the placeholder as the only label. Add a real label.
- Don't validate on every keystroke before the first blur.

## Variants

### size

- `sm` — For dense forms and toolbars.
- `md` — The default size for most forms.
- `lg` — For prominent, high-emphasis forms.

## States

- `default` — At rest and ready to accept typing.
- `focus` — The field has keyboard focus and shows a focus ring.
- `error` — What the user typed didn't pass validation, and the message says why.
- `disabled` — Can't be typed in or tabbed to.

## Accessibility

- **Role:** `textbox`
- **Keyboard:** Standard text-editing keys apply.
- **Keyboard:** Tab moves focus to and from the field.
- Give every field a label element that points at it. A placeholder disappears as soon as the user types, so it can't do this job.
- In the error state, set aria-invalid and link the message with aria-describedby so screen readers announce it.
- Mark a decorative leading icon aria-hidden so it isn't announced.
